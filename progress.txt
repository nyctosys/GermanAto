# Progress log (append-only, Ralph style)

## Codebase patterns
- API: FastAPI + SQLAlchemy 2 sync in api/app; routers in api/app/routers; models in api/app/models.py; one Alembic revision per story that changes tables (autogenerate, then check with `alembic check`).
- New numbered documents: add the kind to api/app/numbering.py PREFIXES, call next_number(db, actor.branch, kind).
- Permissions live in api/app/permissions.py; routes use require("perm"); add the permission there and to DEFAULT_ROLES where it fits.
- Money records always carry proof_id or no_proof_reason (CHECK constraint) and reuse estimates.Proof; bank/wallet need a reference or screenshot.
- Stock only changes through app.stock.move(); do not db.refresh() an item after move() (it discards the unflushed average cost).
- Web: Next.js 16 App Router, Tailwind v4 tokens in globals.css, zustand for shared state, zod schemas in web/lib/schemas.ts with parseForm; shared components in web/components (ui, payments, estimates, purchasing, print).
- Pressable things must look pressable (DESIGN.md 6b): filled ghost buttons, underlined links, chevron on whole-row links (class row-link).
- After editing globals.css, Turbopack may serve stale CSS: stop the web preview, rm -rf web/.next/dev, restart.
- Browser checks: scan every new screen at 320/375/768/1280 for sideways scroll, clipped text, small touch targets.
- Push: git -c credential.https://github.com.helper= -c 'credential.https://github.com.helper=!/usr/local/bin/gh auth git-credential' push https://github.com/nyctosys/GermanAto.git dev:refs/heads/dev

## US-502 (journal engine)
- app/journal.py: post(db, branch, memo, [Line(code, debit, credit)], on=, source=(type,id)); reverse(); live_entry(); balances(); sync_opening(). Ledger codes in CHART; money accounts map via MONEY_CODE.
- journal_entries/journal_lines are append-only through a DB trigger (migration 0011); tests build tables with create_all so the trigger is not exercised there.
- Post inside the same transaction as the event, right before db.commit().
## US-503 (post journals for events)
- app/posting.py holds one function per event; stock.move() posts every movement itself, so never post stock entries elsewhere.
- Shared rounding/totals live in app/pricing.py (estimates re-exports them).
- Add new money events by writing a posting.* function and calling it before db.commit() in the route; add a reconciliation test in test_phase5_money.py.
- Dev DB backfill: uv run python -m app.backfill_journal
## US-504 and US-505 (money in/out)
- MoneyEntry (migration 0012) holds other income, owner capital, expense, drawings, transfer; customer payments (Payment) and vendor payments stay in their own tables and are merged by routers/moneybook.py into /money-in and /money-out.
- Web: components/moneybook.tsx is shared by both pages; entrySchema in lib/schemas.ts mirrors the API rules.
- zsh: do not use ${var^} in shell heredocs; write files from python instead.
## US-506 (credit notes and refunds)
- Alembic does not detect changed CHECK constraints: edit the migration by hand (see 0013) and name foreign keys so downgrades work.
- Invoice balance = total - credit notes - (payments - refunds); negative means refundable. Refund MoneyEntry carries invoice_id or payment_id.
- Held advances exclude refunded ones everywhere (_held_advances, quotation totals, visit cancel guard).
## US-507 (daily cash close)
- cashclose.assert_day_open(db, branch_id, {accounts}, date) is the lock check; call it from any new route that records or voids money on a past date.
## US-508 (missing evidence)
- Rows from moneybook._gather carry source_type and signoff; month-end checks (US-701) should use /api/missing-evidence open count.
## US-509 (inspection repairs to job card, extra work approval)
- Repairs link to a job card through InspectionRepairLink (by index) and only from SIGNED inspections, so indices can't shift.
- JobCardLine.proposed_price must be carried through job card saves (the web sends it back) and starts the quotation price.
- Browser state (scan functions on window) is lost when navigating the pane: do not navigate while a background scan runs.
## US-601 to US-604 (HR)
- Attendance days come from app/attendance.py summarise(); payroll uses the same function, so screens and pay always agree. TIMEZONE env (default Asia/Karachi) turns device wall-clock times into UTC.
- Device push is /iclock/cdata (no session): registered serial + optional secret via ?token= or X-Device-Secret. Resends are ignored; unknown pins are kept and claimed when an employee gets that device number.
- A day's pay = salary / working days in the month; deduction = (absent + unpaid leave) days; late days cost nothing. Salary advances are MoneyEntry kind salary_advance (Dr 1300 Employee advances); payroll approval posts Dr 6100 / Cr 1300 recovery / Cr 2400 net; paying posts Dr 2400 / Cr money.
- Next.js pages cannot export extra names: shared constants belong in components/.
- Layout checker (touching cards/controls, overflow) lives in this session's notes: scan sibling section.rounded-card gaps < 8px and controls < 6px apart; section pills on the inspection page were the only offender.
## US-701 to US-706 (month end, reports, dashboard)
- app/reports.py holds every figure; routers/reporting.py, periods.py and the dashboard are thin wrappers, and the closing pack reuses them. Journal lock: journal.post() refuses entries dated in a closed month or year (JournalError -> HTTP 409 via a handler in main.py).
- Reconciliation tests (test_phase7_periods_reports.py) prove receivables, payables and stock value equal their ledger accounts.
- Print pages: components/print.tsx PrintBar (Back, Print, Share as PDF via html2canvas-pro + jsPDF, Send on WhatsApp). Every new print page must pass back, name and (for customer documents) whatsapp.
- Reports page ranges live in the query string (useRange) so links are shareable; CSV via lib/csv.ts.
## US-801 to US-804 (messaging)
- app/messaging.py: events and reminders only queue (messaging.queue), sending is dispatch(); no Twilio env = dry run, messages stay queued. Tests swap messaging._override for a fake provider.
- Dedupe keys (messages.dedupe_key unique) make events and reminders idempotent; reminders send only the latest due step.
- Webhooks verify X-Twilio-Signature (HMAC-SHA1 of PUBLIC_URL + path + sorted fields) and return 503 when TWILIO_AUTH_TOKEN is unset.
- ui.Select used to drop its own classes when given a className; it now merges them.
## US-901 (server packaging and backups)
- docker-compose.yml (db, api, web, optional sync profile), api/Dockerfile (migrates on start), web/Dockerfile (API_URL is a build arg: Next bakes the /api rewrite in). Docker daemon was not running on the dev Mac, so images were NOT built here; `docker compose config` passes.
- deploy/backup.sh and restore.sh tested with BACKUP_LOCAL=1 against a scratch Postgres: dump, files, checksums, pruning (KEEP), restore, damaged backup refused. Scripts avoid GNU-only flags so they run on macOS and Linux.
- Env sample is workshop.env.example because .gitignore ignores .env.* and *.env.
## US-902 to US-904 (sync)
- app/sync.py applies events with Core statements (skips the audit/outbox hook so nothing echoes back); (origin_branch_id, origin_seq) in sync_inbox is the idempotency key; apply_events stops at the first failure so order is kept and returns the last safe seq (acked).
- Conflict = same version, different content (ignoring updated_at/by). Known limit written in the guide: unequal edit counts resolve silently to the higher version.
- Worker is sync_worker.run_once(db, branch, transport) so tests use a fake transport; HttpTransport is stdlib urllib. Pull cursor skips rows it filters out so it never stalls.
- Tokens live in sync_credentials (hash only), not on branches, because branch rows themselves are synced.
- Conflict list is stacked rows, not a table: tables scrolled sideways at 320px.
